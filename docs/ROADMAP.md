# 路线图

这份文件只放**还没做**的事与验收口径。已交付的能力看 [README](../README.md)
的功能表与 [DEPLOY](DEPLOY.md) 第八节的实测记录；页面上的"未生效项"说明以
设置页为准（`nw_config.UNHONORED`）。

原则（和现有代码一致）：

- 核心后端继续**只依赖 Python 标准库**。需要模型、需要推送协议这类绕不开的
  外部能力，一律做成**可选旁路**：装了就用，没装就明说降级，不能让主链路起不来。
- 前端继续 ES5 单页、无构建步骤。
- 不新增"页面有开关但代码没消费者"的设置项；没做就不放进页面。

## 1.3.0 交付了什么（以及和原计划的差异）

原计划第 5~10 项的落地情况，**按实际实现写，不按计划的措辞写**：

| 项 | 状态 | 与原计划的差异（要说清的） |
|---|---|---|
| 5 本地 AI 检测 | 已交付 | 推理是**进程内** `onnxruntime`（不是子进程），线程数钳到 ≤2，只在已判定有动静的窗口抽帧；模型与依赖由用户自取，没装就明确显示"未安装"。音频事件、可选 VLM 一句话描述、"昨天下午谁在客厅"自然语言检索都在。**没做**：计划里那份"与人眼标注的召回/误报对照表"——那需要标注素材，本项目没有，所以不声称准确率 |
| 6 隐私与合规 | 已交付 | 遮蔽烧进像素（四条链路：直播/录像/小米/导出，配了遮蔽就强制重编码）、访问审计 JSONL（90 天）、导出默认遮蔽 + 文件名中性化、保留期上限 **365 天**（计划里举例写的 90，取 365 是因为家用盘也允许留一年，0 = 不自动删仍是明确选项） |
| 7 存储可靠性 | **部分** | 已交付：完整性自检（空洞 / 0 字节段 / 时长不符，`/api/integrity` 异步扫描 + 页面结果表）、rclone 冷层归档（校验后才删）。**未交付**：SMART 体检、回收站式删除、"打包某天某路"的备份出口 —— 见下面第一节 |
| 8 回放增强 | **部分** | 已交付：倍速、按事件键盘跳转、片段导出与免登录分享链接。**未交付**：逐帧步进、时间轴悬停缩略图、多路同步回放 —— 见下面第二节 |
| 9 PWA + Web Push | **部分** | 已交付：PWA 外壳（manifest + SW，只缓存壳与静态资源，视频流一律 network-first）与本地通知深链。**明确没做**：Web Push / VAPID —— 见下面第三节 |
| 10 多用户与权限 | 已交付 | 角色实现为 **admin / read 两档**（计划里写的"管理员/观看/回放"三档没有必要：观看与回放在这套接口上本就是同一组读权限）。越权回 **404 不是 403**，与计划的验收措辞不同，理由写在 [SECURITY.md](SECURITY.md) |

## 还剩的：存储可靠性（原第 7 项未做的三块）

**要解决的问题**：现在能滚删、能告警空间不足、能扫出空洞，但"盘坏了会不会提前知道"、
"删错了能不能找回"没有答案。

**落地要点**

- **SMART 体检**：定时读 `smartctl`（没装就跳过并说明），把关键属性
  （重映射扇区、待映射、温度）接进 `/api/health` 与 `/api/metrics`，
  只做只读探测，不碰磁盘策略。
- **回收站式删除**：清理循环不直接 `unlink`，先移入 `<rec>/_trash/<日期>/`
  保留 24 小时再真删；被事件引用的段照旧留到最后。归档（`nw_archive`）
  已经是"远端校验通过才删本地"，但滚删这条路没有缓冲。
- **备份出口**：提供一个"把某天某路的分段 + 事件索引打成一个包"的命令行工具
  （stdout 或指定目录），方便用户自己 rsync 到异地；不内置云上传。

**验收**

- 人为 kill -9 录像进程，重启后坏段被识别并隔离，回放列表不出现黑段
  （扫描已经能报出来，缺的是"隔离"这一步）。
- 清理后 24 小时内可在回收站找回；超过 24 小时的自动消失，磁盘占用回到预期。
- SMART 不可用（容器无权限/无 smartctl）时健康检查不因此变红，只在自检里提示。

**明确不做**：内置 RAID 管理、自动格式化、替用户决定删哪块盘。

## 还剩的：回放增强（原第 8 项未做的三块）

- **逐帧步进**：前后各一帧，跨分段连续。倍速与事件跳转已交付，逐帧要处理
  MPEG-TS 与 MP4 两条链路的 seek 精度，单列出来，别混在倍速里做。
- **时间轴悬停缩略图**：按需生成并缓存（别一次性把盘读穿）。事件缩略图已经有了
  （`/api/events/<cam>/thumb/...`），缺的是"任意时刻"的抽帧与孤儿文件清理。
- **多路同步回放**（2~4 路同屏对齐时间）：放在最后，先看单路体验是否够用。

**验收**

- 逐帧在跨分段边界不乱序、不黑屏；1× 行为与现在完全一致。
- 悬停缩略图在冷缓存下 500 ms 内出图，热缓存 < 100 ms，且不产生大量孤儿文件。

## 还剩的：Web Push（原第 9 项明确没做的半块）

现状：PWA 外壳装得上主屏幕，通知走 `showNotification` —— 这要求**页面还开着**。
关掉浏览器就没有系统级提醒，这条只能靠邮件 / 企业微信 / 钉钉 / Bark / Webhook。

为什么 1.3.0 不做 VAPID：

- 订阅端点由浏览器厂商的推送服务持有，推送那一刻**必须**公网可达且有真证书；
  内置自签 8443 不满足。做完也只是在"真证书 + 反向代理"这一种部署形态下可用，
  而那是本项目里最少的那类安装。
- 需要生成并落盘一对 ES256 密钥、维护每设备的订阅台账、处理端点失效回收。
  这套东西在"纯标准库、无账号体系"的前提下要做对，成本明显高于它带来的提醒价值。

**如果要做**：密钥落 `data/`（与配置同权限边界）、订阅端点存配置、正文只放
"哪一路、什么时间、有没有事件"且**不附画面**、点开进 App；环境不满足时设置页
显示"当前环境不可用 + 原因"，不假装成功。邮件/IM 渠道保持不变，Web Push 是并列
的一条，不替代。
