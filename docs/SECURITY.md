# 安全

一台 NVR 存的是你家 24 小时的画面。这个文件说清楚**哪些地方会咬人**，
以及本项目已经替你堵了哪些、哪些必须你自己做。

## 必做三件事

1. **设登录密码**（装完第一件事，页面会引导你）。
2. **别把 8088 直接透到公网。** 8088 是明文 HTTP，口令穿过局域网时是明文。
   要外部访问：前面放带真证书的反向代理（[DEPLOY.md 第四节](DEPLOY.md)），
   或者用你自己的 VPN（WireGuard / Tailscale 等）。
3. **给 go2rtc 开 BasicAuth**，即使它只绑回环。理由见下。

## 已实现的防护

| 面 | 做法 |
|---|---|
| 口令存储 | PBKDF2-HMAC-SHA256，12 万轮 + 16 字节随机盐；**明文不落盘**，备份配置拿不到口令 |
| 会话 | `secrets.token_urlsafe(32)`，只在内存；Cookie `HttpOnly + SameSite=Strict` |
| CSRF | 靠 `SameSite=Strict` 挡掉：跨站请求不带这个 Cookie |
| 暴力破解 | 按 `IP+用户名` 限流：15 分钟 8 次失败 → 冷却 30 秒 |
| 会话生命周期 | 滑动续命，上限可配（默认 24 小时，最短 5 分钟）；改密码即刻作废所有旧会话 |
| 认领窗口 | 未设密码时**只放行"设密码"这一个接口**，录像/配置/直播流全部要登录态 |
| 会话表 | 最多 200 条，超出按插入序淘汰（防内存涨） |
| 静态资源 | 非 `/api` `/live` `/rec` 前缀放行 —— 页面本身要能告诉访客"你还没登录" |
| 健康检查 | `/api/health` 免登录，但只回**收敛结论**；存储占用、看门狗心跳、每路明细只在登录态下发 |
| 录像下载 | `/rec/**` 要登录态；路径经 `normpath` + `realpath` 双重归一后强制落在录像根内（`..` 穿不出去），且只允许命中文件 —— 不做目录列表 |
| 路径解码后的 `..` | 路由入口对**解码后**的路径再查一次 `..` 分段，直接 400 —— 否则 `%2e%2e/config.json` 会被单页应用回退成 `index.html` 并回 200，看起来"没越权"其实是守卫被绕过了 |
| 地址脱敏 | 对外回显的 RTSP/流地址里的口令会被替换成 `user:***@`（`_mask_url`）；ffmpeg/ffprobe 的报错原话走 `_mask_text`，配置读回接口只回"已设置"标志 |
| 告警出门脱敏 | 邮件 / 企业微信 / 钉钉 / Bark / Webhook 的正文与标题在发送前统一抹掉流地址口令（`nw_notify._mask_creds`）—— 故障详情来自 ffmpeg stderr，那句里通常带着完整的 `rtsp://user:pass@host`，而邮件会进收件箱、Webhook 会进第三方日志 |
| 完整地址按需取 | 列表与状态接口只给掩码；要看原文走 `GET /api/cameras/<id>/secret`，**仅管理员**，且每次调用都进审计（`cam_secret_reveal`） |
| 多用户与按摄像头授权 | 角色只有 `admin` / `read` 两档；只读用户带一份摄像头白名单，越权时回 **404 而不是 403** —— 免得别人靠状态码把你的摄像头数量数出来 |
| 访问审计 | 登录、失败、锁定、改密、增删用户/摄像头、越权、取原文、看直播/回放、导出、分享、扫描、归档都写 JSONL（`<data>/audit/YYYYMMDD.jsonl`，保留 90 天）；字段名含 `pass/token/secret/hash/salt` 的值一律 `***` |
| 隐私遮蔽 | 遮蔽区域烧进像素（`drawbox`，`black@1:t=fill`），直播、录像、小米取流、导出四条链路都挂；**配了遮蔽就强制重编码**，`storage.source=RAW` 的流拷贝分支会让位 —— 否则遮蔽只是播放器上的贴纸 |
| 导出与分享 | 导出默认带遮蔽；下载文件名是中性任务号（`homeeye-<id>.mp4`），不带摄像头真名；分享链接 `secrets.token_urlsafe(18)`，有效期 0.1–720 小时、可撤销、命中计数，过期后从磁盘台账里清掉 |
| 保留期上限 | `storage.retention_days` 落盘前钳到 0–365 天，防止把家用 NVR 配成事实上的永久留存（0 = 明确不自动删，页面与文档都点名） |
| 网关 socket | 飞牛统一网关模式下按 `umask 007` 创建（0770），与飞牛应用惯例一致 |
| TLS | 内置自签 8443（对讲的硬性要求，见 README）；对外请换真证书 |

## 分享链接是这道门上唯一主动开的洞

免登录、带有效期，这是它的功能，也是它的风险：

- 拿到链接的人**不需要账号**就能看那段画面，链接会进聊天记录、邮件、浏览器历史。
- 分享页会显示**摄像头真名**（"主卧"这类）—— 要分享前请先想清楚这个名字能不能给出去。
- 因此导出下载文件名做了中性化，但页面标题没有 —— 这是取舍，不是疏忽：页面上不说清是哪一路，接收方也没法确认拿对了片段。
- 能撤销就撤销；`/api/shares` 能看到每条链接的命中次数与到期时间，到期即 404。

## go2rtc 这一层为什么最容易漏

go2rtc 的 API 会把它自己的完整配置回给任何能连上它的客户端 —— 里面就有
**米家 `passToken`**，拿到它等于拿到你米家账号的设备控制凭据。

两个反直觉的点：

- `api.listen: "127.0.0.1:1984"` **不等于安全**。go2rtc 源码
  `internal/api/api.go` 判的是 `if localAuth || !isLoopback(...)`：
  `local_auth` 默认 `false` 时，"只绑回环"等于**没鉴权** ——
  同一台机器上的任何进程（包括别的容器、别的用户）都能调你的云台、读那份配置。
- 所以 `docker/go2rtc.yaml.example` 里 `username`/`password` 留空是**故意让你填**，
  并且 `local_auth: true` 已经写死在模板里。填完这一项再联网。

HomeEye 侧对应 `ptz.g2r_user` / `ptz.g2r_pass` 两个设置项，填成一样的即可。

## 摄像头自身的账号

- RTSP 摄像头的用户名/口令存在 `data/config.json` 里（明文，因为要拼进
  `rtsp://user:pass@host/...` 交给 ffmpeg）。所以 **`data/` 目录权限就是这些凭据的
  权限边界**：不要把它挂给别的容器、不要放进任何同步盘、不要提交到 git。
- 米家授权缓存存在 `data/xiaomi_auth/`。
- Docker 版容器内进程是 root（`HE_DATA_DIR=/data`）；飞牛 fpk 版是 `homeeye`
  应用账号，目录权限由系统管。两种都别把 `data/` 设成 777。

## 对讲

上行是浏览器采到的 PCM 分块 POST 给 HomeEye，再转 G.711 推给 go2rtc。
这条链路上的敏感点是：**它能让你家的摄像头喇叭出声**。所以它和其它写操作一样
在登录闸门后面，且必须走 HTTPS（浏览器规矩，不是本项目的偏好）。

## 日志

`info.log`（fpk）与容器日志（Docker）里会有：摄像头主机地址与端口、流路径、
看门狗的修复动作（含 IP 漂移前后的地址）、`[env]` 自检结论、go2rtc 的 API 地址。
这些是拓扑信息，不是凭据，但足够让外人知道你家有几路、什么型号、什么地址。

ffmpeg/ffprobe 的 stderr **不原样落日志**：它被收在每路的内存尾部（300 字符）里，
只在状态接口和告警正文中出示，而这两处都过口令抹除 —— 报错原话里那句
`rtsp://viewer:密码@192.168.1.9: Connection refused` 到外面只会是
`rtsp://viewer:***@192.168.1.9: Connection refused`。

审计文件（`data/audit/*.jsonl`）按字段名抹除，含 `pass/token/secret/hash/salt`
的值一律写成 `***`，但它记录了**谁、从哪个 IP、在什么时间看了哪一路** ——
这份东西本身比口令更敏感，别共享。

结论没变，只是理由变了：**`data/` 目录不是脱敏存储**。
不要把 `data/` 或容器日志上传到任何公开地方、不要把日志卷挂给别的服务。
